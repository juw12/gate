A merge gate for AI‑agent code.

Many parallel agent sessions go in; a small number of tested, risk-tiered, provenance-tagged commits come out. Humans review only what policy says needs a human.

01 / The run

What happened in the recorded run

  • 26 agent sessions submitted work: features, three deliberately broken changes, two pairs of racing edits, one change to an auth path, a 900-line change and one leaking a token.
  • Every feature merged after its tests passed. The broken ones were rejected by the test suite, and the losing side of each race was bounced as a conflict.
  • The auth change waited for a human (gate approve); the oversized change was sent back to be split; the leaking change was blocked without echoing the secret.
  • A post-merge check found main green, and every landed commit carries provenance trailers (session, model, tool, spec, risk tier, approver).

02 / Audit

Evidence an auditor can re-run

gate audit rebuilds a provenance report from the target's own history: every change that reached it, which model and tool made it, under which spec and risk tier, who approved it, every automatic revert, every attempt the gate refused, and every commit that reached the target without the gate.

gate audit --since 2026-10-01 --until 2026-11-01 --out audit-2026-10.md
gate --json audit                 # same data as one JSON document
gate audit --strict               # exit 2 on any finding

Anyone with the repository can re-run it and get the same table. Run gate audit --strict in CI to fail the build on a direct push or an unapproved high-risk change.

03 / Throughput

Throughput, measured

From python bench.py --sessions 160 --lanes 8 --test-seconds 2 --batch 8 on one Windows laptop (Git 2.55, Python 3.13), with a 2 s sleep standing in for CI.

Against github.com through a corporate HTTP proxy, each publish held the lock about 9 s, a ceiling of roughly 77k merges/day at batch 8. A weekly workflow re-runs batch, crash-recovery and push-race scenarios against a real GitHub remote.

04 / Install

Try it

pip install git+https://github.com/juw12/gate
cd your-repo
gate init        # detects your test command
gate spawn fix-1234
gate submit fix-1234 --model <model-id>
gate queue --drain --parallel 8

Standard library only. Python 3.11+, Git 2.40+. MIT licence.

Still out of scope

  • Semantic conflicts are caught after the fact (gate verify bisects and reverts), not prevented.
  • Secret redaction is best-effort; plug in an external scanner for fail-closed coverage.
  • State is files, not a database. Sharing across hosts is tested by simulation, not on a real NFS cluster.
